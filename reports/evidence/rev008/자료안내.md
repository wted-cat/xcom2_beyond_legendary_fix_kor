# 전술 검증 자료 읽기

최종 배포본에서 반복한 보석·병종 전수 결과는 release-roll, 실제 정신 공격·공황·교리 주사위는 actual-stat-rolls.json에서 확인한다. 배포 과정별 기록은 chosen-combinations.csv, chosen-forecasts.csv, poison-pairs.csv, poison-multi.csv, poison-field.json, attack-effect-order.csv, attack-card-effects.csv, permanent-effects-final.csv, strategy-choice-orders.csv, sectoid-loot-checks.json에 있다. before-passives에는 중복 방지와 추가 카드 수정을 넣기 전의 수치가 있다.

전설 및 위태로운 갈망 설정, 전장별 파일 해시와 실제 완료 배치는 test-environments.json과 fixture/session-provenance.json에 있다. 기본 AI 적 턴, 지정된 AI 분기, 직접 시전, 효과만 실행한 대조는 모드 작업 보고서의 해당 표에서 확인한다. 선택 ID는 poison-options.csv의 0부터 시작하는 번호다. R6|ACT의 프레임 번호는 해당 전장·배치와 함께 읽는다.

재검사에는 Python 3가 필요하다. 압축을 푼 뒤 verify_evidence.py를 실행한다. 설치 ZIP 경로를 첫 인자로 주면 63개 배포 파일 전체의 SHA-256도 비교한다. fixture/observer는 전술 빠른 시작용 관찰 모듈이다. 동일한 구성의 독립 시험 설치에서 Scenario=49와 FirstTrial·LastTrial로 배치를 정한다. FinalGroup의 순서·설정은 session-provenance.json과 관찰 모듈의 SameBattleD를 참조한다. 배포 모드 설치에는 관찰 모듈이 필요하지 않다.

추가 병종·바샤르는 extra-observer의 FirstTrial 51~52, 전리품·와이트·전략 선택은 replay-observer의 53~66에서 확인한다. supplement-observer의 67~69는 마그나 바이퍼와 실제 정신 공격 주사위 수정 전 대조다. final-observer의 68~89에서는 배포본을 다시 검증했다. 68~74, 75~87, 88~89를 독립 전장에서 실행한 기록을 사용했다. confirm-observer의 90~92는 섹토이드 실전 턴이다. 같은 모듈의 0~3을 새 전장에서 실행한 CatalogLoot는 배포본의 전체 캐릭터 목록과 전리품 비교를 제공한다. cooldown-observer의 92는 재사용 대기 상태 제출 뒤 능력 객체를 다시 읽어 대기 턴과 다음 실제 행동을 함께 확인한 전장이다.

fixture/analysis는 이 작업의 원본 로그와 검증 폴더 구조를 사용하는 집계 코드다. 압축 안에서 독립 실행하는 결과 검사는 루트의 verify_evidence.py를 사용한다.
